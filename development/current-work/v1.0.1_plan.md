### 2.4 Gaps

Task 1 must be complete (or explicitly deferred with maintainer approval)
before preflight.

> **Known environment caveat (recorded 2026-07-21, v1.0.0 Task 6):** on this
> maintainer's machine, `jupyter nbconvert --execute` resolves notebook
> kernels via the globally-registered `python3`/`ce_test_kernel` kernelspecs
> (`%APPDATA%\jupyter\kernels\`), which point at the system Python install,
> **not** `venv-release`. `make release-preflight`'s "Editable install
> (release tree)" step only refreshes `venv-release`'s own metadata, so the
> global kernel's separate editable install of `calibrated_explanations` can
> drift stale (observed frozen at `1.0.0rc1` during v1.0.0 GA notebook
> execution, silently unrelated to the version actually being released).
> Before running preflight for this milestone, confirm the global kernel
> environment reports the correct version:
> `python -c "import calibrated_explanations as ce; print(ce.__version__)"`
> using the system Python that `%APPDATA%\jupyter\kernels\python3\kernel.json`
> points to; if stale, run `pip install -e ".[dev]"` in that environment
> before/after preflight's file-prep step bumps `pyproject.toml`. This is a
> local-machine setup issue, not a code defect — no durable fix (e.g. a
> `venv-release`-scoped kernel, or having preflight refresh all discoverable
> editable installs) has been implemented; consider one if this recurs.
