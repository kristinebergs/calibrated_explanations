### D3 resolution (2026-07-08, user decision)

Unknown-kwarg policy is **fail-fast**: unrecognized public kwargs raise
`ConfigurationError` (not `UserWarning`), consistent with the Global Rules
exception-class mapping already stated below (line ≈78: "removed/unknown kwargs" →
`ConfigurationError`) and with Task 2–4's fail-fast precedent in this same milestone.

**Caveat requiring a CHANGELOG entry:** this reverses previously shipped behavior.
v0.11.4 Task 15 (`development/finished-work/v0.11.4_plan.md`, closed 2026-06-18)
implemented `UserWarning` ("received unknown keyword arguments ... will be ignored")
for unrecognized kwargs in `WrapCalibratedExplainer._normalize_public_kwargs`. Task 5
must add a `CHANGELOG.md` entry under `## [Unreleased]` that explicitly documents this
reversal — unknown public kwargs to `WrapCalibratedExplainer` / `CalibratedExplainer`
explain surfaces now **raise** `ConfigurationError` instead of warning — so users
relying on the v0.11.4 warn-and-ignore behavior are not silently broken.

Decision D1 (RC version string `1.0.0rc1`) is **not** in scope here — version-string
alignment for RC remains v1.0.0-rc Task 6. This milestone uses the standard dev-bump
convention only (`0.11.6-dev` → `0.11.6` at tag).

## Global rules

- **No new deprecation cycles.** Every behavior change ships as a fail-fast bug fix with
  a CHANGELOG migration note; no `DeprecationWarning` with a removal ETA may be introduced.
  `make deprecation-closure` must remain green throughout.
- **Ledger attribution stays `Removed in: v0.11.5`.** Users lost documented support for
  the removed symbols in v0.11.5; v0.11.6 fixes the *enforcement* (silent-pass → raise).
  The v0.11.6 CHANGELOG records this as a bug fix ("removed kwargs were silently ignored;
  they now raise"), not as a new removal. Error messages may continue to say
  "removed in v0.11.5".
- **Exception classes.** Import from `calibrated_explanations.utils.exceptions`;
  always pass a `details=` dict. Fail-fast errors here use `ConfigurationError`
  (removed/unknown kwargs) and `ValidationError` (invalid values), consistent with
  the ADR-039 remediation posture.
- **Fallback visibility.** Any retained fallback path emits `UserWarning` + INFO log per
  CONTRIBUTOR_INSTRUCTIONS.md §5; the preferred resolution in this milestone is to raise.
- **TDD per defect class.** Each finding gets a regression test written first (failing on
  pre-fix code). Tests follow `test_should_<behavior>_when_<condition>` naming, extend the
  nearest existing test file, seed RNG with 42, no network, no wall clock.
- **CHANGELOG.** Every behavior change lands under `## [Unreleased]` in the same PR.

## 4) Coercer fail-fast: normalization strategy and interval summary (bug-list Findings 3–4; ledger item 7)

### 4.0 Goal

Two coercion helpers silently substitute a default for any unrecognized input:
`coerce_normalization_strategy()` (`calibration/normalization_strategy.py` ≈64–87)
returns `SCALE` for any bool or typo string; `coerce_interval_summary()`
(`core/prediction/interval_summary.py` ≈24–29) returns `REGULARIZED_MEAN` for any
invalid value. In particular, `VennAbers.predict_proba(normalize=True)` silently
delivers `SCALE` semantics while the docstring promises `COHERENCE`. Resolve both per
the fallback-visibility policy.

### 4.1 Implementation steps

1. **Record the product decision:** (a) raise `ValidationError` on unrecognized input
   (preferred; consistent with the ADR-039/D3 fail-fast posture), or (b) keep default
   substitution with `UserWarning` + INFO log per CONTRIBUTOR_INSTRUCTIONS.md §5.
   Chosen: **(a) raise `ValidationError`** (2026-07-08, user decision). Consistent with
   the fail-fast pattern already applied in Tasks 2–3; avoids adding a warn+log path for
   input that is being actively closed as a sink, not kept as a documented compatibility
   shim.
2. Apply the decision to both coercers. Bool input to `normalize=` must not silently mean
   `SCALE` under either option.
   Status: Done. `coerce_normalization_strategy()` raises `ValidationError` for any
   value that is not a `NormalizationStrategy` member or a matching (case-insensitive)
   string — this includes bools and `None`, so the legacy `normalize=True/False`
   passthrough now fails fast instead of resolving to `SCALE`. `coerce_interval_summary()`
   raises `ValidationError` for any value that is not `None`, an `IntervalSummary` member,
   or a matching string; `None` is preserved as the "caller omitted the parameter"
   sentinel and still resolves to `REGULARIZED_MEAN` (required — `VennAbers.predict_proba`'s
   `interval_summary=None` default flows straight into the coercer on every default call,
   and `CalibratedExplainer.__init__`/`predict` rely on the same sentinel).
3. Update the `VennAbers.predict_proba` `normalize=` docstring

   `True→COHERENCE` / `False→NONE` mapping the code never implemented — to match the
   implemented behavior.
   Status: Done. Docstring now states the bool passthrough is removed and raises
   `ValidationError`; added a `Raises` section.
4. Update `docs/migration/deprecations.md` if the ledger's "Bool passthrough removed"
   wording no longer matches the implemented behavior.
   Status: Reviewed — no change needed. The ledger row (≈253) already reads "Bool
   passthrough removed; use enum or string value," which now matches the implemented
   (raising) behavior.
5. Regression tests for both coercers: bool input, typo string, and a valid enum/string
   input each produce the decided behavior.
   Status: Done. `tests/unit/calibration/test_normalization_strategy.py` (bool, typo,

   unrecognized type, `None`-default, valid string/member) cover both coercers; added

## 5) ADR-038 parameter-surface hardening and public API graduation (former RC Task 0b)

### 5.0 Goal

Close the v0.11.6 ADR-038 scope as one coherent parameter-surface hardening task:
audit every public `**kwargs` boundary, make closed public surfaces fail fast on typos
and removed aliases, preserve the documented experimental plugin-forwarding seam, and
keep `WrapCalibratedExplainer` and direct `CalibratedExplainer` behavior aligned before
the v1.0.0 release candidate.

This task closes the v0.11.6 D3/D4 decisions and the follow-up defects found while
implementing them. It does **not** reopen the separate ADR-038 graduation gate for
replacing the residual experimental explanation-plugin `**kwargs` seam with explicit typed
arguments; that remains governed by ADR-038 as a later graduation item.

### 5.1 Status assessment

Status update 2026-07-08: Completed. The original Task 5 grew through several
follow-up investigations: dead/internal allow-list names, cross-method kwarg scoping,
direct `CalibratedExplainer` parity, single-source allow-lists, legacy plot forwarding,
and `calibrate()` state preservation. Those are now treated as one Task 5 closure, not
as separate sub-tasks.

### 5.2 Consolidated findings and decisions

1. **Closed public surfaces fail fast.** Unknown kwargs on closed/enumerable public
   surfaces now raise `ConfigurationError`, replacing the v0.11.4 warn-and-forward
   behavior. This applies at the public boundary, before kwargs can disappear into an
   internal `**kwargs` sink.
2. **Removed aliases are rejected consistently.** Removed guarded kwargs, reject-path
   `confidence=`, and removed `normalize=` are all handled by explicit removed-alias
   checks. `normalize=` is not a synonym for `normalization=`; it is a removed alias and
   must fail at the wrapper/core boundary.
3. **The allow-list is real, scoped, and single-source.** Live documented names are
   accepted; dead names (`condition`, `condition_label`, `condition_labels`,
   `include_reject_details`) and internal-only names (`output_interval`, `y_threshold`)
   are rejected; and wrapper allow-lists are derived from `CalibratedExplainer`
   allow-lists rather than duplicated by hand.
4. **Per-method scoping replaces the old flat known-name set.** A name valid on one
   public method but invalid on another now raises `ConfigurationError` instead of being
   accepted and silently ignored. The wrapper reports the rejecting method in the error
   message.
5. **Direct `CalibratedExplainer` use gets the same protection.** `__init__`,
   `predict`, and `predict_proba` are closed fail-fast surfaces. `explain_factual` and
   `explore_alternatives` reject cross-surface contamination while preserving the
   ADR-038 experimental plugin-forwarding exception for genuinely plugin-defined kwargs.
6. **Intentional aliases and internal seams are explicit.** `mondrian_categorizer=` is
   an intentional alias for `mc=` on `calibrate()` and conflicts with `mc=` fail fast.
   `_ce_skip_reject` remains an internal direct-core escape hatch and is not accepted by
   the wrapper.
7. **Bug fixes discovered during hardening are in scope.** Legacy global plotting now
   forwards only prediction-relevant kwargs into gated prediction methods, and rejected
   `calibrate()` calls preserve a prior successful calibration instead of clearing
   `calibrated` before validation completes.

### 5.3 Implementation steps

1. Audit `WrapCalibratedExplainer`, direct `CalibratedExplainer`, reject-orchestrator,
   plotting, and plugin-forwarding kwargs surfaces against ADR-038 D3/D4.
2. Add or reuse shared parameter helpers for unknown public kwargs, removed guarded
   kwargs, removed reject kwargs, removed normalization kwargs, and cross-surface kwargs.
3. Replace the wrapper's flat `_KNOWN_PUBLIC_KWARGS` behavior with method-scoped

## 9) Local verification profile cleanup and development-loop simplification

### 9.0 Goal

Refactor the local verification entrypoints so contributors and agents can use checks that are proportional to the development phase:

1. **Inner loop:** very fast checks while editing.
2. **Task verification:** focused evidence that a release-plan task is complete.
3. **PR preflight:** blocking PR-scope checks before opening/updating a PR.
4. **Main/full/release gates:** expensive checks only before merge, release, or explicit maintainer request.

The current `make local-checks-pr` is too heavy for routine use because it mixes PR checks, governance scanners, all non-viz tests, optional docs/notebook/dependency work, and repeated pre-commit execution. This slows v0.11.6 implementation and encourages contributors to skip local verification entirely. The cleanup must preserve merge/release confidence while reducing routine development latency.

> **Status addendum 2026-07-09 (pre-v2-gaps P1):** the second-pass audit found that
> the task mappings covered only Tasks 1–11 when this task was marked complete, so
> the §9.2 mapping requirement was not actually met for Tasks 12–21. Closed
> 2026-07-09, and the design was inverted at maintainer request so it survives
> future release plans: the mappings now live in **this plan's** fenced
> `toml ce-task-verification` block (see "Task verification mappings
> (machine-readable)" before the release gate summary), and `scripts/local_checks.py`
> is a generic engine that parses the active plan (`ACTIVE_RELEASE_PLAN` pointer,
> `--plan` override). Every non-optional task (1–21 and 23–29) is mapped, and
> unsupported ids fail with a clean error listing the supported set — so a
> `local-checks-task` verification line without a matching mapping fails at run
> time. (A test file that additionally asserted the profile/task wiring,
> `tests/scripts/test_local_checks_profiles.py`, was removed by Task 29 as
> release-plan meta-testing; the engine's own fail-fast error is the durable
> enforcement.)

### 9.1 Definitions and intended command semantics

Introduce or normalize these local profiles:

| Profile   | Make target                              | Purpose                                                                               | Expected use                                              |
| --------- | ---------------------------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| `quick`   | `make quick` / `make local-checks-quick` | Inner-loop checks: lint/format/type/import-boundary/basic fast tests                  | Run repeatedly while coding                               |
| `task`    | `make local-checks-task`                 | Focused release-task verification: `quick` + task-relevant tests/gates                | Run before marking a release-plan task complete           |
| `pr`      | `make local-checks-pr`                   | Blocking PR-scope preflight, no release/main/nightly work                             | Run before opening/updating a PR                          |
| `full`    | `make local-checks-full`                 | Full local gate approximating PR + main checks                                        | Run before merge or maintainer-requested final validation |
| `release` | `make local-checks-release`              | Release-oriented local verification, including docs/capability/release-specific gates | Run only during release preparation                       |

`quick` and `task` must be distinct. `quick` optimizes developer feedback. `task` is the minimum defensible completion evidence for a release-plan task.
