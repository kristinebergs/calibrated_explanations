## Global rules

- **No new deprecation cycles.** Every behavior change ships as a fail-fast bug fix with
  a CHANGELOG migration note; no `DeprecationWarning` with a removal ETA may be introduced.
  `make deprecation-closure` must remain green throughout.
- **Ledger attribution stays `Removed in: v0.11.5`.** Users lost documented support for
  the removed symbols in v0.11.5; v0.11.6 fixes the *enforcement* (silent-pass → raise).
  The v0.11.6 CHANGELOG records this as a bug fix ("removed kwargs were silently ignored;
  they now raise"), not as a new removal. Error messages may continue to say
  "removed in v0.11.5".
- **Exception classes.** Import from `calibrated_explanations.utils.exceptions`;
  always pass a `details=` dict. Fail-fast errors here use `ConfigurationError`
  (removed/unknown kwargs) and `ValidationError` (invalid values), consistent with
  the ADR-039 remediation posture.
- **Fallback visibility.** Any retained fallback path emits `UserWarning` + INFO log per
  CONTRIBUTOR_INSTRUCTIONS.md §5; the preferred resolution in this milestone is to raise.
- **TDD per defect class.** Each finding gets a regression test written first (failing on
  pre-fix code). Tests follow `test_should_<behavior>_when_<condition>` naming, extend the
  nearest existing test file, seed RNG with 42, no network, no wall clock.
- **CHANGELOG.** Every behavior change lands under `## [Unreleased]` in the same PR.

## 9) Local verification profile cleanup and development-loop simplification

### 9.0 Goal

Refactor the local verification entrypoints so contributors and agents can use checks that are proportional to the development phase:

1. **Inner loop:** very fast checks while editing.
2. **Task verification:** focused evidence that a release-plan task is complete.
3. **PR preflight:** blocking PR-scope checks before opening/updating a PR.
4. **Main/full/release gates:** expensive checks only before merge, release, or explicit maintainer request.

The current `make local-checks-pr` is too heavy for routine use because it mixes PR checks, governance scanners, all non-viz tests, optional docs/notebook/dependency work, and repeated pre-commit execution. This slows v0.11.6 implementation and encourages contributors to skip local verification entirely. The cleanup must preserve merge/release confidence while reducing routine development latency.

### 9.1 Definitions and intended command semantics

Introduce or normalize these local profiles:

| Profile   | Make target                              | Purpose                                                                               | Expected use                                              |
| --------- | ---------------------------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| `quick`   | `make quick` / `make local-checks-quick` | Inner-loop checks: lint/format/type/import-boundary/basic fast tests                  | Run repeatedly while coding                               |
| `task`    | `make local-checks-task`                 | Focused release-task verification: `quick` + task-relevant tests/gates                | Run before marking a release-plan task complete           |
| `pr`      | `make local-checks-pr`                   | Blocking PR-scope preflight, no release/main/nightly work                             | Run before opening/updating a PR                          |
| `full`    | `make local-checks-full`                 | Full local gate approximating PR + main checks                                        | Run before merge or maintainer-requested final validation |
| `release` | `make local-checks-release`              | Release-oriented local verification, including docs/capability/release-specific gates | Run only during release preparation                       |

`quick` and `task` must be distinct. `quick` optimizes developer feedback. `task` is the minimum defensible completion evidence for a release-plan task.

### 9.2 Required behavior

#### `quick` profile

Must run only checks that are cheap enough for repeated use:

1. Ruff check on source/tests touched by normal development, or all `src`/`tests` if changed-file detection is not implemented.
2. Ruff format check.
3. Phase-1B mypy scope.
4. ADR-001 import-boundary check.
5. ADR-002 exception/compliance check.
6. Fast pytest subset:

   * default: `pytest -q tests/unit -m "not viz and not slow" --maxfail=1 --no-cov`
   * do not run coverage
   * do not run docs
   * do not run notebooks
   * do not run dependency audit
   * do not run performance benchmarks
   * do not run capability evidence refresh
   * do not run full ADR-030 audit unless the changed files require it

#### `task` profile

Must run `quick`, then add focused task verification:

1. Accept explicit focus arguments, for example:

   * `make local-checks-task TASK=3`
   * `python scripts/local_checks.py --profile task --task 3`
   * `python scripts/local_checks.py --profile task --paths <changed paths>` if path-aware routing is implemented.
2. For v0.11.6 tasks, define at least these focused mappings:

   * Task 1: deprecation-closure gate tests + `make deprecation-closure`
   * Task 2: guarded-kwarg regression tests + affected wrapper/core tests
   * Task 3: reject-policy unknown-kwarg tests + affected reject/orchestrator tests
   * Task 4: normalization/interval-summary coercer tests + affected Venn-Abers tests
   * Task 5: ADR-038 kwarg-surface audit tests + public API snapshot check if signatures changed
   * Task 6: warning-policy tests + `make warning-policy`
   * Task 7: docs/instruction consistency checks + strict docs build if public docs changed
   * Task 8: `ncf="entropy"` tests + targeted ruff check
   * Task 9: local verification-profile unit tests + instruction-sweep checks
3. Produce a short machine-readable report under `reports/local_checks/task_profile_report.json` containing:

   * selected profile
   * task id, if supplied
   * commands run
   * skipped heavy gates with reason
   * exit status
4. Do not run release/main/nightly checks unless the task mapping explicitly requires them.

#### `pr` profile

`make local-checks-pr` must stop being the routine inner-loop command. It should run blocking PR-scope checks only:

1. `quick`
2. docstring coverage
3. logging-domain enforcement
4. STD-001 nomenclature enforcement
5. parameter naming guard
6. capability-chain validation
7. raw evidence structural validation only, not evidence refresh
8. private-member scan
9. ADR-030 anti-pattern detector
10. test-helper export guard
11. trust-mutation primitive guard
12. ConfigManager usage guard
13. marker hygiene
14. generated-report local-path guard
15. all non-viz tests with no coverage: `pytest -q -m "not viz" --no-cov`

It must not run optional heavy checks merely because they are optional. Optional/advisory should mean “available through a heavier profile”, not “always run but ignore failures”.

Do not run `pre-commit run --all-files` twice. Run it at most once in PR/full/release profiles, and do not run it in `quick` unless explicitly requested.

#### `full` and `release` profiles
