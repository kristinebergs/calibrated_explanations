## Global rules

- **No planned implementation.** Every task in this plan is a validation, release-note, or documentation-correction task. Sections labelled "Implementation steps" mean verification, release-note, or documentation-correction steps only, not feature implementation.
- **Emergency patch exception.** If a release-blocking defect is found, the fix is written and merged as an emergency patch (separate PR, full gate re-run). The defect, fix, and re-verification evidence must be recorded in the release notes under "Release-blocking defect patches."
- **Gate before tagging.** All six task checklists and the release preparation checklist must be complete before the RC tag is cut.
- **Deprecation ledger empty.** `make deprecation-closure` must report zero blocking deprecations. Any active deprecation left in the ledger must either target v1.0.0 removal or have an explicit post-v1.0 deferral that is not RC-blocking.
